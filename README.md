# RF GAME CENTER

یک وب‌سایت Node.js برای معرفی و انتشار فایل APK اندروید، همراه با پنل مدیریت خصوصی، آپلود نسخه جدید و آمار درخواست‌های دانلود.

## امکانات

- طراحی واکنش‌گرا با تم مشکی و قرمز
- صفحه اصلی فارسی و صفحه مدیریت در مسیر `/admin`
- تغییر نام، توضیحات و شماره نسخه بازی
- آپلود APK و جایگزینی فایل قبلی
- دانلود مستقیم از مسیر `/download`
- دیتابیس SQLite برای تنظیمات، نشست مدیر و گزارش دانلودها
- رمز مدیر و کلید نشست از Environment Variables
- محدودیت تلاش ورود، محدودیت درخواست دانلود، اعتبارسنجی فایل APK و محافظت CSRF
- ثبت شناسه تصادفی دانلود، زمان، نوع تقریبی دستگاه و مرورگر
- عدم ذخیره IP و اطلاعات هویتی کاربران
- جلوگیری تقریبی از شمارش دوباره: هر مرورگر در هر بازه ۳۰ دقیقه‌ای برای هر نسخه یک بار شمرده می‌شود

> شمارنده، درخواست دانلود را ثبت می‌کند؛ نه نصب موفق یا اجرای بازی را.

## پیش‌نیازها

- Node.js نسخه 20 یا جدیدتر
- npm
- هاست Node.js که اجرای برنامه دائمی و فضای ذخیره‌سازی پایدار (Persistent Disk/Volume) داشته باشد

## اجرای محلی در ویندوز

1. Node.js نسخه 20 یا جدیدتر را نصب کنید.
2. پوشه پروژه را از ZIP خارج کنید.
3. در ترمینال وارد پوشه `rf-game-center` شوید.
4. دستور زیر را اجرا کنید:

   ```bash
   npm install
   ```

5. فایل `.env.example` را کپی کنید و نام نسخه کپی را `.env` بگذارید.
6. در `.env` مقدار `ADMIN_PASSWORD` را با رمز قوی و منحصربه‌فرد (حداقل ۱۲ نویسه) جایگزین کنید.
7. برای ساخت کلید نشست تصادفی، در ترمینال اجرا کنید:

   ```bash
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```

   خروجی را در `SESSION_SECRET` قرار دهید. فایل `.env` را به هیچ‌کس ندهید و در Git یا ZIP عمومی منتشر نکنید.

8. برای اجرای محلی، مقدار `NODE_ENV` را در `.env` روی `development` بگذارید؛ سپس:

   ```bash
   npm start
   ```

9. سایت را در `http://localhost:3000` و پنل را در `http://localhost:3000/admin` باز کنید.

## انتشار روی Hostless (راهنمای مخصوص)

Hostless برنامه‌های Express را به‌صورت App از مخزن Git مستقر می‌کند. بنابراین ZIP را ابتدا Extract کنید و فایل‌های پروژه را در یک مخزن Git (مثلاً GitHub یا GitLab) قرار دهید؛ خود Hostless در این مسیر از مخزن متصل‌شده Deploy می‌کند. راهنمای رسمی: [Express روی Hostless](https://docs.hostless.cloud/javascript/express).

1. وارد داشبورد Hostless شوید و از **Create resource → App** یک App بسازید.
2. ارائه‌دهنده Git، مخزن پروژه و شاخه انتشار را انتخاب کنید. Build System را روی تشخیص خودکار نگه دارید.
3. اگر Start Command خودکار تشخیص داده نشد، `npm start` را وارد کنید. دستور نصب وابستگی‌ها از `package.json` و به‌صورت خودکار انجام می‌شود.
4. در **Settings → Environment variables** این متغیرها را اضافه کنید:

   - `NODE_ENV` = `production`
   - `ADMIN_PASSWORD` = رمز مدیر قوی و اختصاصی (حداقل ۱۲ نویسه)
   - `SESSION_SECRET` = خروجی دستور ساخت کلید تصادفی که در بخش اجرای محلی آمده است
   - `DATA_DIR` = `/data`
   - `UPLOAD_DIR` = `/data/uploads`
   - `MAX_APK_SIZE` = `1073741824` (اختیاری؛ ۱ گیگابایت)
   - `DOWNLOAD_LOG_RETENTION_DAYS` = `0` (اختیاری؛ بدون حذف خودکار گزارش‌ها)

5. در بخش Storage هنگام ساخت App یک Volume ایجاد و به مسیر مطلق `/data` متصل کنید. دیتابیس SQLite، نشست‌ها و APKها در این مسیر ذخیره می‌شوند. اگر Volume را در مسیری دیگر متصل کردید، `DATA_DIR` و `UPLOAD_DIR` را مطابق آن تغییر دهید.
6. برای این نسخه که از SQLite محلی استفاده می‌کند، تعداد Replicaها را روی **1** نگه دارید؛ SQLite روی دیسک محلی بین چند نمونه برنامه به‌صورت خودکار هماهنگ نمی‌شود.
7. App را ایجاد و Deploy کنید. Hostless مقدار `PORT` را خودش فراهم می‌کند؛ برنامه روی `0.0.0.0` گوش می‌دهد. پس از موفقیت Health Check، آدرس HTTPS ساخته‌شده را باز کنید.
8. آدرس‌های زیر را آزمایش کنید:
   - `/` صفحه عمومی
   - `/admin` پنل مدیر
   - `/api/game` اطلاعات عمومی بازی
   - `/download` دریافت APK (پس از آپلود)

برای تغییر Environment Variables، Hostless نسخه جدید را Deploy می‌کند. بعد از هر Deploy بررسی کنید Volume همچنان به `/data` متصل باشد. فایل‌های خارج از Mount Path ممکن است با جایگزینی نسخه برنامه باقی نمانند. از Volume و فایل‌های APK بکاپ جداگانه بگیرید.

### نکته‌های مهم استقرار

- Hostless از Appهای Node.js و Express پشتیبانی می‌کند؛ **Static Site** برای این پروژه کافی نیست، چون این سایت به بک‌اند Node.js نیاز دارد.
- `better-sqlite3` یک ماژول native است؛ اجازه دهید Hostless وابستگی‌ها را در مرحله Build نصب کند و در صورت شکست Build، گزارش Deploy را بررسی کنید.
- فایل APK بزرگ ممکن است به محدودیت اندازه درخواست در هاست یا پراکسی برخورد کند؛ محدودیت Hostless را با `MAX_APK_SIZE` هماهنگ کنید.
- تنظیمات Environment Variables را از مسیر **Settings → Environment variables** انجام دهید؛ مقادیر محرمانه را در سورس یا مخزن Git قرار ندهید.
- پیش از انتشار عمومی، در صفحه Deployments موفقیت Build و Health Check را بررسی کنید.

## بارگذاری APK و مدیریت

1. به `/admin` بروید و با `ADMIN_PASSWORD` وارد شوید.
2. در بخش «اطلاعات بازی» نام، نسخه و توضیحات را ویرایش و ذخیره کنید.
3. در بخش انتشار فایل، APK را انتخاب و آپلود کنید.
4. پس از موفقیت، دکمه دانلود در صفحه اصلی فعال می‌شود.
5. نسخه جدید، فایل قبلی را جایگزین می‌کند. از APK قبلی قبل از انتشار نسخه تازه بکاپ بگیرید.

صفحه مدیریت حداکثر ۱۰۰ درخواست اخیر را نشان می‌دهد. آمار کلی و خلاصه نسخه‌ها نیز در همان صفحه موجود است.

## حریم خصوصی و محدودیت آمار

- IP ذخیره نمی‌شود.
- شناسه دانلود تصادفی است و برای شناسایی هویت واقعی کاربر طراحی نشده است.
- اطلاعات مرورگر و نوع دستگاه از User-Agent به‌صورت تقریبی استخراج می‌شوند.
- برای کاهش ثبت تکراری، یک شناسه تصادفی first-party در کوکی مرورگر قرار می‌گیرد؛ پاک‌کردن کوکی، مرورگر دیگر یا دستگاه دیگر می‌تواند باعث ثبت دوباره شود.
- دانلودی که در گزارش ثبت می‌شود لزوماً به معنی تکمیل دریافت، نصب یا اجرای بازی نیست.

## پشتیبان‌گیری

قبل از انتشار نسخه جدید یا تغییر هاست، از کل پوشه `data/` و `uploads/` بکاپ بگیرید. فایل `.env` را جداگانه و در محل امن نگهداری کنید.

## نکات امنیتی

- از رمز مدیر منحصربه‌فرد و طولانی استفاده کنید.
- `SESSION_SECRET` را محرمانه نگه دارید و پس از افشا آن را عوض کنید.
- `.env` را عمومی نکنید.
- سایت را فقط با HTTPS منتشر کنید.
- محدودیت آپلود هاست باید با `MAX_APK_SIZE` هماهنگ باشد.
- بررسی ZIP signature یک کنترل اولیه است؛ پیش از انتشار عمومی APK، آن را با ابزارهای امنیتی معتبر اسکن و روی دستگاه آزمایشی بررسی کنید.
